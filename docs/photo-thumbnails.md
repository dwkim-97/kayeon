# 사진 썸네일 운영

Supabase 유료 Image Transformations 대신 앱의 Node.js API와 sharp로 WebP를 생성한다.

## 배포

- `pnpm install --frozen-lockfile` 후 일반 Next.js 배포를 수행한다.
- 기존 `NEXT_PUBLIC_SUPABASE_URL`과 서버 전용 `SUPABASE_SECRET_KEY`를 사용한다.
- DB 마이그레이션, Pro 전환, 사진 재업로드는 필요하지 않다.
- 원본을 이미 공개 제공하는 `profile-photos` 버킷을 사용한다. 버킷 권한을 변경하지 않는다.

## 동작

- `/api/photos/thumbnail?path=<원본 경로>&width=<크기>`에서 240/650/1200px 변형만 처리한다.
- 최초 조회 시 비율을 유지하고 자르거나 확대하지 않는 WebP(품질 75)를 생성한다.
- 결과는 `_thumbnails/v1/<크기>/<원본 경로>.webp`에 저장한다. 기존 사진도 첫 조회 때 자동 적용된다.
- 이후에는 저장된 파일을 읽고, 브라우저 1시간/CDN 1일 캐시를 사용한다.
- 변환 실패·시간 초과·과부하 시 원본으로 307 응답한다. 이 응답은 캐시하지 않는다.
- 저장만 실패하면 생성된 이미지는 그대로 제공한다. 이 경우 다음 요청에서 다시 생성될 수 있다.
- 원본 내용은 공개 URL로만 읽는다. 서버 비밀키는 변형 저장/삭제와 원본 존재 여부의 메타데이터 확인에 사용한다.
- 사진 삭제 시 해당 원본의 세 가지 변형도 함께 삭제한다. 기존 브라우저/CDN 캐시는 만료까지 남을 수 있다.
- 프로필 전체의 상세 사진 사전 다운로드는 하지 않고, 열린 프로필만 미리 읽는다.

## 제한과 확인

첫 조회에는 원본 다운로드·변환·저장 시간이 필요하다. 이후 조회에서 저장/캐시 효과가 난다.
변환은 인스턴스당 최대 4개, 대기 포함 최대 64개로 제한하고, 8초 이상 대기하거나 전체 요청이 22초를 넘으면 원본을 사용한다.
이미지 원본은 최대 10MB/2,500만 화소까지 변환한다. 제한을 넘으면 원본으로 표시한다.
Supabase 유료 변환 요금은 발생하지 않지만 일반 Storage 용량/전송량과 앱 서버 실행량은 사용한다.

배포 후 Network에서 `/api/photos/thumbnail`이 `200 image/webp`인지 확인한다.
307만 반복되면 원본 접근, 서버 키, Storage 쓰기, sharp 런타임을 확인한다.
원본 경로는 업로드마다 새 UUID를 사용한다. 같은 경로의 파일을 덮어쓰는 방식으로 바꾸면 캐시 버전도 갱신해야 한다.
